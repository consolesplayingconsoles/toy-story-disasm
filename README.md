# Toy Story disassembly

A disassembly of the Mega Drive **Toy Story** (Traveller's Tales, 1995), in progress. It rebuilds
the ROM byte for byte from source generated by its tools (one file per routine, every branch and
reference a label), with the engine's dispatch idioms, its text format and its graphics format
mapped, and tools to unpack the compressed art and read the sprites.

**This repository contains no game code or data.** You supply your own ROM; `setup.sh` generates
everything game-derived on your machine, and the traces hold addresses and diff ranges only.

| Europe + French patch | 4,194,304 | `f7237963d94ff25054a43fd01ab464ae5bbb477` (one character short in the notes: not recorded in full) | diff partner: the text |
| USA + Indonesian patch | 4,194,304 | `f0181d510065112f2e7e382d56652a69316d676a` | diff partner: the text |

The two are separate compiles, not a patch of each other: about 98% of the bytes differ, so
addresses do not carry over. Facts are recorded per revision and anchored by byte signature where
practical. The fan translations used for diffs are listed in `log/toy_story_facts.py`.

## Building

You need your own copy of the USA ROM (a `.zip` holding it is fine), Python 3 with `capstone`
(`pip install capstone`), and AS, Alfred Arnold's macro assembler (`asl` and `p2bin`).

```
echo 'AS_PATH="/path/to/the folder with asl and p2bin"' > .env     # once (not committed)
bash setup.sh "path/to/your ROM"
bash build.sh
```

`build.sh` ends with `MATCH`. The source is in `build/src/`; `AGENTS.md` is the loop for working on
it. Set `PYTHON` in `.env` too if your `python3` is not the one with `capstone`.

The other tools take the ROM path as an argument:

```
python3 tools/trace.py <rom> traces/trace_usa.json [<hex seed> ...]
python3 tools/rnc.py <rom> list
python3 tools/rnc.py <rom> extract <hex offset> out.bin
python3 tools/frames.py <rom> <hex frame> <hex palette> out.png
```

## What is here

| | |
|---|---|
| `log/toy-story-notes.md` | the narrative: identity, dispatch idioms, coverage, text, graphics |
| `log/toy_story_facts.py` | the structured facts, per revision, with a confidence per entry: identities, names (`NAMES_USA`), the region map (`REGIONS_USA`, `RNC_BLOCKS_USA`) |
| `traces/` | the USA and EU/PAL traces (addresses only: code, labels, data references), the ROM-to-ROM diff ranges, and the rebuild record |
| `AGENTS.md` | how to work on the disassembly: name, make symbolic, decode, build |
| `setup.sh`, `build.sh` | check your ROM, then regenerate the source, assemble it and compare: `MATCH` |
| `tools/rebuild.py` | the ROM as source, assembled with AS and compared; writes `traces/rebuild_usa.json` |
| `tools/trace.py` | recursive-descent 68000 tracer |
| `tools/rnc.py` | Rob Northen ProPack (RNC) decoder: list or extract the compressed blocks |
| `tools/frames.py` | sprite frame decoder: pieces, or a PNG with a palette |
| `tools/frame_blocks.py` | splits every identified frame into header and tiles for the rebuild (`log/toy_story_frame_blocks.py`) |
| `tools/` (others) | listing, cross references, entropy map, ROM diffs, header, IPS/BPS |
| `tools/progress.py` | the Progress block below |

## Engine

Three dispatch idioms carry most of the indirect flow, and the tracer resolves all three: a table of
`bra.w` instructions reached by a computed `jmp`/`jsr` (the largest, 38 entries at EU `$271E`, has
two callers), an unrolled copy or fill loop entered part way in, and a word-relative jump table
indexed by an object's state and event. Five calls remain unresolved: real per-object function
pointers loaded from a struct field at run time. The boot path has the standard Mega Drive region
check on `$A10001`. Details and addresses in the notes.

## Text

Plain 7-bit ASCII, uppercase, padded to fixed-width slots and bounded by quote marks: two fan
translations (French, Indonesian) swap readable ASCII in place. The two-word header before each
string and the lookup mechanism are not decoded yet.

## Graphics

The compressed art is Rob Northen ProPack (RNC): 264 blocks in the USA ROM, all of which decode
with a matching checksum. Sprites use a piece-list frame format; Woody's frames are run-length
coded, objects' are raw. Buzz Lightyear's frames, grouped by pose, and his palette are in
`GRAPHICS_USA`.
